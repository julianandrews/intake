# Message

Your output may include an optional top-level `message` string of one or two
short sentences; put it before any `[[...]]` table. intake shows it to the user
above the confirmation prompt. Use it only when the user needs context to judge
the proposal: an assumption you had to make, a guess where the data was
uncertain, a choice between plausible foods, or a question the user can answer
with feedback.

Most proposals need no message. Omit the field when your choices are clear and
well supported. Do not narrate what you did, restate the proposal, or list
routine steps. Keep it to plain text — no bullets, headings, or multi-paragraph
explanations. Never replace the proposal with a message: always produce a
complete result, make the best choice you can, and note any assumption so the
user can correct it. When you revise after feedback, update or remove the
message if it no longer applies.
